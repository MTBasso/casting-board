Judging: Terminal Cards design system

Area: the "Terminal Cards" reference doc (published as the reviewed artifact) against its live source, src/ui/season/season.css, and the six screens that ship it (src/ui/season/*.tsx). Nothing was run or screenshotted — this is a read of the CSS, the TSX, and the reference doc's own claim to be verbatim.

Every card below is a reconstruction from source, not a screenshot.

Contract (from the tokens + doc)

Fonts
SF Mono/Courier New for HUD/labels/log; Georgia for names, titles, end-states (the "cold readout vs. warm name" split, stated by the doc itself).
Color roles
Dark-only (no light mode). Accent teal (--sn-accent) reserved for the one forward action + HP; gold (--sn-gold) for fatigue/legendary/rarity; red (--sn-danger) reserved for "this fight punishes you" + lost states.
Radii
14px cards, 8–12px controls, pill badges/tags.
States
Cards: hover lift + .is-picked glow. Buttons: default / .is-primary / :disabled. Bench cards: .is-active.
Never
HP bar color never doubles as a warning (the number does); accent never fills more than one surface at a time.

F1 — Dim text fails contrast at the sizes it's actually used

high
Computed WCAG contrast, --sn-text-dim #6b7480 on its two backgrounds: 3.91:1 on --sn-panel-2, 4.09:1 on --sn-bg — both below the 4.5:1 floor for text under 24px. It's applied at 9–11px in .sn-meta, .sn-label, .sn-bar-row, .sn-eyebrow-adjacent copy (src/ui/season/season.css:44,58,183,237).

These are exactly the labels carrying game state — fatigue %, HP %, "Switch in — bench" — on the smallest type in the system. A player skimming mid-fight is the one who needs this text most legible.

F2 — No focus style is defined for a dark, borderless UI

high
grep -n focus src/ui/season/season.css returns nothing across all 428 lines — no :focus or :focus-visible rule anywhere, on .sn-btn, .sn-card, or .sn-bench-card (all real <button> elements, confirmed in AnteScreen.tsx:139-150).

Every interactive surface here is a borderless or dark-bordered rounded rect on a near-black background — exactly where a browser's default focus ring is easiest to lose. Keyboard users get whatever the browser ships, unstyled to the system.

F3 — Primary buttons sit well under a comfortable tap target

medium
.sn-btn { padding: 9px 0; font-size: 12px; } with no explicit line-height (season.css:144-152) — resolved height is roughly 32-34px. The top-level CLAUDE.md describes increMon as an idle PWA, implying phone-width play, not desktop-only.

Bench cards and shop buttons are the exact controls a player taps repeatedly mid-run; a sub-44px target on a phone screen is the classic mis-tap source, worse under a chunky drop-shadow card that visually reads bigger than its hit area.

F4 — The system has no documented empty, loading, or error state

medium
All 7 sections of the reference doc cover color, type, buttons, badges, cards, meters, and log/end-states. grep -rin "loading\|error\|empty" src/ui/season/*.tsx finds nothing but an <img loading="lazy"> attribute in DraftScreen.tsx — no .sn-empty, no error-state class in season.css.

A bench with a free slot, a shop that rolled nothing you can afford, a draft pool that's run dry — these are real reachable states in the roguelike-run structure (REDESIGN.md), and none of them has a system answer yet, only whatever each screen improvises.

F5 — The reference doc is missing the layout class that makes the fight screen work

low
season.css:217-222 defines .sn-matchup { display: grid; grid-template-columns: 1fr auto 1fr; gap: 18px; } — the wrapper that actually places the two .sn-fighter panels either side of .sn-vs. The doc's "07 — Log & End States" and its fighter-adjacent classes never show this class or the composed row.

The doc calls itself "verbatim" from the CSS, but a future screen author copying classes out of it has no way to see how the VS layout is actually assembled — they'd have to go read the CSS anyway, defeating the doc's stated purpose.
